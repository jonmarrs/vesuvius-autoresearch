## Prepared description

**In one sentence:** Clarify that fiber evaluation retains tracer-generated
`trace` spans and measures agreement with their saved interpolation between
annotator control points.

**One real example:** A local audit of all 620 PHerc0139 and 233 PHerc0332
published annotation JSON files on October 23 found 13,862 and 2,422 `trace`
spans respectively, all with recorded beam width 8, lookahead 2 and cone angle
25 degrees. Reference selection excludes Lasagna spans while retaining these
traced spans, so the dense reference is not necessarily independent of the
tracer being evaluated. See [#2264](https://github.com/ScrollPrize/villa/issues/2264).

**Before:** The documentation describes the selection policy but does not
explain that eligible dense geometry may have been generated by the tracer.

**After:** One paragraph explains that interpretation and points to per-span
provenance. Scoring only control points is identified as a separate protocol.

**Proof:** The audit covered all 853 listed files and bound each parsed file
by SHA-256. Counts of interpolation modes, settings and recorded source
manifests are preserved in the Autoresearch
[report](https://github.com/jonmarrs/vesuvius-autoresearch/blob/3ed95b80c30c55edfa9709a99d63deb83bbefcab/reports/fiber_reference_provenance_2026-10-23.md).
The change is documentation only; the current documented selection policy and
`reference_cases()` wrapper were checked at Villa `e2254ebe`.

**Why / where this is useful:** It helps readers interpret tracer comparisons
using the published fiber annotations. These counts establish provenance;
they do not establish ranking bias or justify a new scoring default.
