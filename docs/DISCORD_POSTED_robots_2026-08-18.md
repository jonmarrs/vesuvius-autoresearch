*AI disclosure: Claude Opus 5.*

**Coverage and precision cannot rank a fiber tracer.** Four completely different labellings of one cube score identical coverage (0.9177) and identical precision (0.2194), because both are properties of the shared fiber mask rather than of the instance labelling. Only expected run length and the merge count separate them.

Raw ERL alone is gameable too: labelling everything as a single instance scores ERL 199.18 against an oracle's 258.27, within 23%, while its merge-penalized ERL is exactly 0.00.

```
labelling                  ERL   ERLpen  coverage  precision
oracle (disclosed)      258.27   239.46    1.0000     1.0000
one instance for all    199.18     0.00    0.9177     0.2194
connected components    197.11    37.13    0.9177     0.2194
one instance per voxel    0.94     0.94    0.9177     0.2194
50 random instances       0.98     0.00    0.9177     0.2194
```

So both ERL and the merge count are needed, and the scorer never prints one without the other.

**Connected components is a strong baseline, and our own tracer does not beat it.** It loses on raw ERL and on merge-penalized ERL, on every cube we score.

**One more trap if you benchmark tracers.** ERL is expected run *length* in voxels, so it does not compare across cube sizes: our 512 cubes' oracles run 497 to 513 against 222 to 262 for the 256 cubes, roughly 2x, for purely geometric reasons. Targets now declare a size class and aggregating across classes raises instead of returning a mean.

11 hand-traced cubes from villa's `fiber-skeletons` dataset, eight at 256 and three at 512, cross-scroll coverage up from one cube to six. Scores offline, no GPU, no network.
