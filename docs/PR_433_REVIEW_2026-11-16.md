## Review outcome

No blocking code defect was found in the combined diff. One documentation issue
was corrected: the TTA adapter no longer promises that stacking views is faster.
It describes the stacked forward and OOM fallback, with throughput dependent on
the model and device. No numerical behavior changed during this PR review.

The review checked these boundaries against the code and regression cases:

- Memory profiling is opt-in, starts after preflight and before model construction,
  and covers all resident ensemble members. CPU lifetime RSS and selected-device
  PyTorch allocator peaks retain distinct sources/scopes. No whole-device peak
  or capacity guarantee is inferred. Primary metadata measurement failure leaves
  no success sidecar. Successful optional coherence gets a later observation.
- TTA rejects malformed batch/rank and batched spatial grids before Villa can
  reshape/deaugment them. Valid scalar outputs, sequential coarser grids, custom
  concatenator timing, parameter names and OOM fallback retain the pinned behavior.
  The Villa leaf itself is unchanged. Mixed regional ink/fiber/global-QC outputs
  use the maintained regional predictor, not this experimental concatenator.
- Gaussian validation rejects invalid/unrepresentable weights before caching,
  preserves default arithmetic, and resolves implicit CUDA indices in cache keys.
  The volumetric example retains valid convolution/gradients while checking depth
  and channels and accurately identifying its random, untrained outputs.
- The direct psutil dependency uses the already-locked 6.0.0 package. The lock
  diff changes dependency metadata only. The two new test modules are in the
  curated registry; the portable profile remains 16 of 224 modules.
